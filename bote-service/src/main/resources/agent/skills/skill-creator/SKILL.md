# Skill Creator（内置）

将用户的任务流程沉淀为可复用的 Agent Skill，支持：

- 从 0 创建新 skill；
- 修改现有 skill（补规则、补资源、改触发描述）；
- 为 skill 生成最小可用测试用例，帮助用户验证。

## 何时使用

出现以下意图时优先触发：

- “帮我做一个 xxx skill”
- “把我们现在这套操作流程做成 skill”
- “这个 skill 不好用，帮我优化”
- “skill 的 description 怎么写更容易被触发”

## 输出目标

默认输出一个可直接使用的技能草案，至少包含：

1. `SKILL.md`（必须，含 frontmatter：`name` + `description`）
2. 可选目录：
   - `references/`：较长文档、规范、流程说明
   - `scripts/`：重复性强、确定性高的脚本
   - `assets/`：模板或静态资源

当用户只要求“先出文案草稿”时，可先只产出 `SKILL.md`。

默认交付展示方式（除非用户明确不要）：

- 在回复中逐个列出本次创建/修改的文件；
- 每个文件都提供完整内容（可直接复制）；
- 每个文件都提供可点击下载链接。
- 下载链接必须来自 `FileSystemTools` 内置上传能力：先将沙箱文件上传到文件服务器，再回填真实下载 URL。

## 标准工作流

### 1) 先澄清意图，再动手

至少澄清以下问题（能从上下文推断的可直接确认）：

1. 这个 skill 要帮用户完成什么？
2. 在什么场景/什么话术下应该触发？
3. 输出结果长什么样（文本、文件、目录、链接）？
4. 有没有约束（工具、环境、命名、格式、权限边界）？

如果信息不足，先提最少量问题补齐关键缺口，不要盲写。

### 2) 设计触发描述（frontmatter.description）

`description` 是触发关键。写法要求：

- 说明“做什么”+“什么时候用”；
- 覆盖用户常见表达（正式说法 + 口语化说法）；
- 避免只写抽象目标，尽量带场景词；
- 不写与能力无关的承诺。

### 3) 编写 SKILL.md 主体

正文建议结构：

1. 技能目标（1 段）
2. 何时使用 / 何时不使用
3. 标准步骤（可执行、可检查）
4. 输出格式约定（必要时给模板）
5. 异常与兜底策略

写作风格：

- 以可执行指令为主，少空话；
- 解释关键规则背后的原因，避免机械堆砌 MUST/NEVER；
- 保持泛化能力，避免只对单一示例有效。

如果本次任务包含多个文件，正文中应额外给出“文件导航区”：

- 文件清单（按目录分组）；
- 每个文件的用途一句话说明；
- 对应下载链接（需为 FileSystemTools 上传后返回的真实 URL）。

### 4) 生成最小测试用例（推荐）

默认给出 2-3 条真实用户口吻的测试提示词，覆盖：

- 标准场景（应触发）
- 边界场景（应触发但输入不完整）
- 近似场景（可能不该触发）

并向用户说明预期结果，便于快速验收。

### 5) 迭代优化

根据用户反馈重点改三类问题：

1. 触发不准（该触发没触发，或误触发）
2. 步骤不稳定（执行路径含糊、重复劳动多）
3. 输出不达标（格式不一致、信息缺失）

每轮只改关键问题，保持 skill 简洁。

## 创建/改造时的硬性要求

- 保留用户明确指定的 skill 名称；未指定时再提建议名称。
- `name` 使用小写短横线风格（如 `skill-creator`）。
- 不生成恶意、误导、越权或数据外泄导向的技能内容。
- 不要求用户使用本系统不存在的工具链。
- 交付时必须包含每个文件的完整内容；不可只给摘要或差异片段（除非用户明确要求）。
- 交付时必须包含每个文件的下载链接。
- 禁止使用相对路径、占位链接或伪链接充当下载地址。
- 必须调用 `FileSystemTools` 将沙箱文件上传到文件服务器，并使用工具返回的 URL 作为最终下载链接。

## 交付清单（给用户确认）

交付时明确说明：

1. 已创建/修改的文件列表
2. 触发描述的核心覆盖范围
3. 建议用户如何做第一轮验证（给出示例提示词）
4. 每个文件的完整内容（可直接查阅、复制）
5. 每个文件的下载链接

推荐交付模板：

1) 文件列表

- `path/to/SKILL.md` - 用途说明
- `path/to/references/xxx.md` - 用途说明

2) 文件内容

- `path/to/SKILL.md`
  - 贴出完整内容
- `path/to/references/xxx.md`
  - 贴出完整内容

3) 下载链接

- `[下载 SKILL.md](https://file-server.example.com/...)`
- `[下载 xxx.md](https://file-server.example.com/...)`

4) 下载链接生成说明（简要）

- 已通过 `FileSystemTools` 上传文件到文件服务器；
- 以上链接均为上传后返回的真实可下载 URL。
